# PRODUCT-1 · 备份恢复可信功能登记

## 1. 开工登记卡

| 项目 | 内容 |
|---|---|
| 稳定 ID / 类型 | `PRODUCT-1` 当前阶段：备份恢复可信 / 完整功能 |
| 用户故事 | 用户导入 JSON、文件夹、Gist 或快照前，能知道备份是否可读、是否属于支持的版本；不可信输入不能创建半成品项目或污染现有数据。 |
| 主归属 | PRODUCT-1 数据主权与开源信任；复用现有 JSON 导入、文件夹、Gist、快照入口。 |
| 取代/下线 | 不新增入口；所有恢复入口统一收口到现有 `importProjectJSON()`。 |
| 本阶段范围 | 版本、项目根记录、登记表数组结构预检；未来版本拒绝；旧格式缺表兼容警告；写库前失败。 |
| 非范围 | 加密备份、云同步、账号、帮助系统、国际化和第三方匿名上报。 |
| 外部依赖 | 仅依赖现有 IndexedDB、`PROJECT_TABLES` 和浏览器本地文件能力；不依赖服务端。 |

## 2. 三注册表四问

| 问题 | 本阶段裁决 |
|---|---|
| AI 读什么 | 不增加 AI 读取能力；预检只读取备份 JSON 的结构，AI 仍完全由既有 `CONTEXT_SOURCES → assembleContext()` 治理。 |
| AI 写什么 | 不增加 AI 写字段；预检和导入不调用 `adopt()`，业务字段仍由现有 `FIELD_REGISTRY / AdoptionSchema` 管理。 |
| 哪些表参与生命周期 | 不新增表、不手写表清单；表形状和项目根校验从 `PROJECT_TABLES` 派生，实际导入/删除/重映射继续复用既有生命周期。 |
| 缺失哪个注册表 | 无缺失；新增入口只有 `backup-trust.ts` 的只读检查器，并通过架构检查禁止旁路导入。 |

## 3. 数据与实现边界

- `inspectProjectBackup()` 在任何 IndexedDB 写入前检查格式版本、项目根记录和所有登记表的数组结构。
- 未来版本、损坏 JSON、缺少项目根记录或错误表形状直接拒绝；旧备份缺少后来新增表只给出兼容警告并按空表处理。
- `json-export`、文件夹、Gist 和快照恢复共用同一个预检入口；失败路径不创建项目、不写入子表。
- 不改变数据库 schema，不增加迁移，不产生并行导入器；现有导入事务负责外键重映射与项目生命周期。

## 4. 验收证据

- 定向回归：`tests/regression/R-PRODUCT1-backup-trust.test.ts`，覆盖损坏、未来版本、兼容缺表和成功导入。
- 浏览器验收：`tests/e2e/core-workflow.spec.ts` 的 JSON 导出、重新导入、快照恢复和数据管理诊断路径。
- 发布门禁：`npm run ci`、`npm run ci:e2e`、架构/三注册表/AI manual/TypeScript/构建检查。

本阶段完成后，PRODUCT-1 的其余产品能力仍需独立登记，不得把本功能的预检能力描述成加密云备份或完整社区身份体系。
