# SIM-1 共享互动运行时设计

> 状态：SIM-1C NPC 演进候选闭环已交付（2026-08-03）；后续进入 TTRPG-1 / CHATGAME-1 产品层
> 依赖：WORLD-1 / CANON-1 / AGENT-1 / FLOW-2
> 服务对象：NPC 演进、单机跑团、角色聊天与文字冒险

## 1. 产品边界

SIM-1 不是新的创作 Canon，也不是某一种游戏的私有存档。它是四类互动体验共同使用的、
可回放本地运行时：

```text
创作 Canon
  └─ 作者明确创建会话时冻结只读来源快照
       └─ SimulationSession
            ├─ RuntimeEvent（唯一状态变化来源，严格追加）
            ├─ RuntimeCheckpoint（可重建加速/命名存档）
            ├─ NPC 演进
            ├─ TTRPG
            └─ 角色聊天/文字冒险
```

红线：

1. 模拟器不得修改章节、角色主档、物品账本或任何创作 Canon 表。
2. AI 只能提出叙事或动作候选；时间、状态、骰子和分支由代码执行。
3. 会话创建后使用冻结快照，作者后续改设定不会静默改写既有存档。
4. 有价值的运行事件回流创作层时必须另建候选并由作者确认，本阶段不提供自动回流。

## 2. 数据模型

### `simulationSessions`

- 项目/世界作用域、体验类型、标题、状态、规则集版本。
- `seed` 是确定性随机根；相同种子、事件序号和骰式必须得到相同结果。
- `initialStateJson` 保存可回放的起始状态；`canonSnapshotJson` 保存创建时的只读创作来源。
- 分支用 `parentSessionId + parentThroughSequence` 记录来源，但拥有独立事件流。

### `simulationEvents`

- `(sessionId, sequence)` 唯一、严格连续、只追加。
- 首期闭集：时间推进、实体写入/补丁/移除、记忆记录、随机判定、叙事记录。
- `payloadJson` 必须先经事件闭集校验，再进入 reducer；未知事件拒绝写入。
- 随机事件保存骰式、每颗骰子、修正值、总值和确定性 nonce，AI 无法改写结果。

### `simulationCheckpoints`

- 保存某序号的完整状态、状态 hash 和作者命名。
- 检查点是派生加速与存档点，不是第二状态源；读取时仍核对 session/sequence。
- 分支从指定序号回放后冻结为新会话 `initialStateJson`，不共享可变记录。

三表都带 `projectId + worldGroupId`，统一登记 `PROJECT_TABLES`，保证项目删除、世界删除、
多世界盖章、JSON 导出/导入和外键重映射由同一生命周期覆盖。

## 3. 运行状态与事件

运行状态 v1：

- `clock`：整数逻辑时间，不绑定现实日历。
- `entities`：以稳定 `entityKey` 索引的角色/NPC/地点/物品/势力/玩家运行时投影。
- `memories`：会话内主体对事件的知道、误解、遗忘与记住；不反写创作认知账本。
- `narratives`：运行时叙事记录，只属于该体验。
- `lastSequence`：最后应用的事件序号。

事件 reducer 是纯函数。回放同一初始状态和事件流必须逐字节得到同一状态；事件序号缺口、
重复、跨项目/跨会话记录或非法补丁全部拒绝。

## 4. 确定性随机

首期支持安全骰式 `NdM±K`：

- 骰子数 `1..100`，面数 `2..1000`，修正值绝对值不超过 `1,000,000`。
- 随机字节仅由 `session.seed + 下一事件序号 + 骰式 + nonce` 派生。
- 判定结果先由代码计算，再与事件在同一事务追加；调用者不能传入自选点数。
- 回放读取已保存结果，不重新掷骰；独立复算可以验证事件未被篡改。

## 5. 分支、检查点与并发

- 所有追加使用 Dexie 事务读取最后序号并写入下一序号，唯一复合索引阻止并发重复。
- 分支可指定父会话任意已存在序号；系统回放到该点，写成子会话初始状态。
- 父会话后续变化不影响子会话；删除父会话时子会话的来源引用置空，子会话仍可独立回放。
- 检查点只加速读取；损坏或 hash 不符时可以从初始状态与事件流重建。

## 6. 分阶段交付

### SIM-1A · Runtime Core

- ✅ 三表 schema / PROJECT_TABLES / 便携生命周期。
- ✅ 事件闭集、纯函数 reducer、严格追加、回放、检查点、分支、确定性骰子。
- ✅ 数据迁移、导入导出、项目/世界删除与并发回归。
- ✅ 体验中心可见会话壳：会话列表、逻辑时间、骰子、叙事、检查点、分支和安全删除。
- ✅ 当前状态与本会话事件日志分层展示；分支继承状态刷新后仍可见。

### SIM-1B · Canon Snapshot + 运行时投影

- ✅ 从作者选择的世界、角色、地点、物品和规则生成结构化冻结快照。
- ✅ 显示每个来源的稳定标识、字段、文本摘要、更新时间与 SHA-256 内容 hash；导入损坏可验出。
- ✅ 将冻结角色/地点/物品投影成独立运行时实体，不保留指向可变 Canon 对象的写引用。
- ✅ 补齐实体状态查看器、世界作用域会话列表、检查点恢复分支与会话来源审计。

### SIM-1C · NPC 演进

- 用户故事：作者在 NPC 演进会话中选择一个冻结 NPC，输入一次演进意图，查看 AI 生成的结构化候选，
  明确确认或拒绝；确认后运行时位置、生命周期、标量状态、叙事经历和可选记忆通过事件回放生效。
- 读：只使用 `CONTEXT_SOURCES.simulationRuntime`，读取当前项目/世界的冻结 Canon 快照和事件回放状态；
  不重新读取可变角色、地点或物品表。上下文源校验快照 hash，并限制来源、实体、记忆和最近叙事的数量。
- 写：AI 没有 Canon 写字段，因此不新增 `FIELD_REGISTRY` 或 `AdoptionSchema`；AI 输出先由严格 parser
  验证，再由 `appendNpcEvolutionProposal()` 写入 `npc.evolution.proposed`，作者确认后由确定性 reducer
  写入 `npc.evolution.accepted`。拒绝写入 `npc.evolution.rejected`，候选因其它事件追加而过期时不可确认。
- 表：不新增表；继续使用已登记的 `simulationSessions`、`simulationEvents` 和现有检查点生命周期。
- 安全边界：只允许 `kind=npc` 或明确标注 NPC 角色进入候选；地点必须是当前运行时已有 `location` 实体；
  不允许新实体、角色类型/来源 ID、Canon 字段或对象/数组型运行时属性；主档、物品流水和正文始终不变。
- 验收：候选在刷新后仍可见；确认/拒绝均可回放并从待处理列表消失；并发追加会使候选失效；跨项目/世界上下文为空；
  UI、事件 reducer、parser 和真实 IndexedDB 隔离项目均有回归证据。

SIM-1B 完成共同引擎与作者 Canon 的只读发布边界，不等于跑团或聊天产品已经完成。
SIM-1C、TTRPG 与聊天只能读取冻结快照和运行时实体，不得重新直连可变作者表。

### TTRPG-1A · 单机战役主持

`TTRPG-1A` 是复用 SIM-1 的第一个产品功能单元，不新增战役表或第二套事件引擎。作者/玩家在跑团
会话中开始一个场景，声明角色回合顺序，提交当前行动；系统可单独执行技能检定，也可让 AI GM 生成
带检定参数和 success/failure 分支的结构化回合候选。作者明确“记录回合”后，代码在同一事务中写入
动作、确定性检定、依据真实结果选择的 GM 叙事和下一行动者。

跑团上下文仍只来自 `CONTEXT_SOURCES.simulationRuntime`，其中额外投影当前场景、回合、动作和检定。
`ttrpg.scene.opened`、`ttrpg.action.recorded`、`ttrpg.check.resolved`、`ttrpg.gm.response.recorded`
与 `ttrpg.turn.advanced` 均禁止通用事件入口直接写入；回合顺序、DC 合计、检定成功状态和候选基线由
reducer/API 校验。AI 不提交骰点、不推进回合、不改变角色/物品/地点和 Canon。

`TTRPG-1B`（规则与遭遇）和 `TTRPG-1C`（长期战役）已分别登记并交付；`TTRPG-1D`
（多人协作）仍需等待 PLATFORM-1，不能因为当前单机战役已可玩就宣称多人跑团体系交付。
