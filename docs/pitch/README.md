# StoryForge OPC 路演材料

## 交付文件

- `storyforge-opc-roadshow.html`：主演示稿，单文件、离线可用，包含动态过渡和演讲者备注。
- `StoryForge-OPC-Roadshow-Backup.pptx`：现场备份，内容与主演示稿一致，采用稳定的静态版式。

## 动态演示稿操作

- 点击页面右侧约 72% 的区域：下一页；点击左侧约 28% 的区域：上一页。
- `←` / `→`、`PageUp` / `PageDown`、鼠标滚轮、触控滑动或底部按钮：翻页；连续反向切换可以随时打断上一段动画。
- `F`：全屏。
- `N`：显示或隐藏当前页讲稿、时间与来源。
- `Home` / `End`：跳到首页或末页。

演示稿内部始终保持 1280×720 的固定逻辑画布，再根据窗口整体等比缩放；浏览器缩放或窗口比例变化不会重新排版正文。建议使用 Chrome 或 Edge 打开并提前进入全屏。文件不依赖外网资源。

## 5 分钟页序

1. 项目主题：故事熔炉
2. 两道断层：想法形成故事、故事进入内容生命周期
3. 三阶段核心路径：故事形成、世界运行、共同生态
4. 世界引擎
5. 长篇小说
6. 节点创作
7. 多人跑团
8. 角色互动
9. 文字游戏实际界面与三类产品形态
10. 市场窗口
11. 早期验证
12. 社区飞轮
13. 产品路线
14. 当前阶段与下一步
15. 愿景收束

每页顶部固定显示五个阶段：`项目主题 → 核心路径 → 衍生产品 → 市场需求 → 未来愿景`，便于评审随时判断当前内容在整套叙事中的位置。

## 7 分钟现场演示建议

- 0:00–0:30：产品总览，说明一个世界被多个功能复用。
- 0:30–2:00：世界引擎，展示世界编号、版本和工作台。
- 2:00–5:00：长篇创作，展示卷章结构、章节上下文、事实与审校能力。
- 5:00–6:30：跑团和角色聊天，明确当前单机能力与多人方向。
- 6:30–7:00：文字游戏实验入口，回扣“从故事到可玩产品”的下一阶段。

讲完第 14 页后直接手动切换 StoryForge 项目开始演示；演示结束后返回第 15 页完成愿景收束。

## 数据口径

- GitHub Traffic 官方窗口只覆盖最近 14 天；主稿采用 2026-07-31 至 2026-08-13 的 14 个完整归档日。
- 6,272 是浏览事件，1,290 是完整克隆事件，均不是独立人数；克隆不包含 `fetch`。
- 约 1,000 为社群成员数，不等于活跃创作者。
- 本地优先产品无法统一统计生成字数和实际创作者数；稿件未虚构该类指标。
- 社群用户的网文发布成果尚缺可公开回执，因此仅在讲稿中作为待核验反馈，不展示收益数字。

## 更新方式

修改构建脚本后运行：

```bash
node docs/pitch/build-roadshow-html.mjs
```

PowerPoint 使用项目工作区提供的 `@oai/artifact-tool` 运行环境生成；构建脚本保留在同一目录，便于后续替换姓名、数据和截图。
